THE WORKSPACE HANDBOOK

Build with confidence.

Real provisioning, separate user access, and honest capability checks.

01 / Install & start

Run the complete installer from this checkout. It installs the Python environment, Node/frontend dependencies and available userspace QEMU tools, verifies the environment, and hosts the panel on port 31120.

bash install.sh
# Or start an already installed checkout:
python skvm.py

The first empty panel gets the hashed administrator login admin / admin123. Keep the forwarded port Private and replace the initial password in Profile. The reminder never blocks navigation. Existing accounts, passwords, guests and workspace-local data are not reset.

02 / Check actual capabilities

python skvm.py check-environment
python skvm.py verify-images
python scripts/qemu-smoke-test.py

QEMU uses userspace TCG by default. KVM requires explicit opt-in, permissions and a passing actual accelerator probe. No LXC, privileged container, systemd, exposed Docker socket or /dev/kvm assumption is required. Missing tools or unverified capacity block creation with the real reason; a trusted external node is an alternative.

The diskless QEMU smoke probe is not an OS boot. Guest allocations always come from that VM’s provisioning configuration. Process/cgroup usage and shared physical host capacity are separate measurements.

03 / Administrator provisioning

Only administrators can create and assign VPS. Choose an enabled owner, node, OS, RAM/vCPU/disk and authentication; review the selected owner’s quota and confirm. Queued/uncertain jobs reserve capacity. A VPS record appears only after real provisioning succeeds. Instances start stopped.

OS image downloads use allowlisted HTTPS, verified endpoints and qemu-img checks. Administrators can pin trusted vendor checksums. Archived releases carry explicit lifecycle warnings; availability is never fabricated.

04 / User workspace

Users land in My workspace, listing only assigned instances. They keep owner power, disk growth, reinstall and delete controls, subject to ownership, quotas and confirmation. Details and My VPS show Start/Stop/Restart according to measured guest state. Delete can stop a running VPS gracefully before removing its storage; failed or unproven shutdown aborts deletion, never silently Force stops. A repeated Start on an already-running guest is a verified no-op. Creation, assignment, host setup and guest network policy are administrative controls.

SSHX guest access

Open a QEMU VM’s Details → Generate SSHX. The panel uses a unique encrypted per-VM management key and runs the following inside that selected guest, never on the panel/node host:

curl -sSf https://sshx.io/get | sh
sshx

The page displays the actual link read from the running client. SSHX must be enabled, the guest must be running with SSH ready, and an administrator must explicitly allow outbound internet. Restricted networking remains the default and is never silently changed. Internet-enabled new guests prepare curl and CA certificates through cloud-init.

{{ icon('shield-alert') }}The SSHX URL is a guest-access secret. Anyone holding it can control the guest outside panel login. Panel sign-out, password changes or disabling a user do not revoke copied URLs. Use Stop SSHX or stop/suspend the VM when finished. Managed clients are limited to at most one hour.

Regeneration stops the prior verified guest client. Timeouts or lost responses become uncertain operations, not fake success. An administrator can inspect the exact guest operation without replaying the installer, or stop the VM to end an uncertain client.

Existing VMs: no reset required

Use Enroll existing VM. Independently verify the displayed guest host-key fingerprint and provide an existing guest password or private key/passphrase. A fixed append-only script installs a management public key; existing owner keys/passwords are preserved. The panel retains only the new encrypted management key, not the supplied enrollment credentials. A host-key mismatch stops authentication before credentials are sent.

Explicit networking

Only an administrator can change a stopped VM’s per-instance policy. QEMU outbound mode also permits reachable host/private services through user networking; use trusted guests or an appropriately isolated dedicated node. It is not an internet-only firewall. Docker instances have no managed SSH daemon/credentials and do not support SSHX.

Native SSH recovery

The details page shows the actual guest username and loopback SSH port on its provisioning host. No public IP or credentials are invented. Run the shown native SSH command on that host or use a real SSH tunnel. Codespaces HTTP forwarding is not a raw SSH tunnel. Keep your own guest recovery credential independently of the panel.

External nodes & backups

Update/restart both panel and agent. The agent advertises SSHX capability and runs fixed guest operations over verified TLS/bearer HTTPS with exact instance checks. No WebSocket or localhost fallback is used. Configure the HTTPS proxy for 180-second request timeouts. Protect and back up the database, original encryption/session keys and appropriate stopped guest storage. See docs/sshx.md and docs/external-nodes.md in this checkout.

The former Console and WebSSH routes/assets are removed; references under docs/reference/ are historical only. Boot logs remain private operator diagnostics, not a panel shell.
